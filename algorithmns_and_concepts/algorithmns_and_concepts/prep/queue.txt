> Queue is an interface

> it has multiple implementation classes like lindkedlist, dequeue and many more

 - q.add() - adds element but throws exception if queue size is fixed and it is full. 

 - q.offer() - adds element will return boolean if element was added and will not throw exception


 - q.remove() - will throw exception if queue is empty

 - q.poll() - will return null if queue is empty


 - q.element() - returns first element, does not remove it, will throw exception queue is empty

 - q.peek() - same as above just returns null if queue is empty

 priority queue

 - elements are not srted
 - on the head there is an element with highest priority


 internally priority queue is a min heap

 min heap is a binary tree such that value of parent is always less than or equal to child

 so time complexity of every operation is log n in priority queue

Blocking queue

it is an interface and ArrayBlockingQueue is implplementing class

this queue is thread safe 

this waits for an event happern - queue to become non empty or wait for space 

simplfy concurrency problems like producer and consumer 

here, 
  - put() blocks and waits for space tobe avaliable is queue is full
  - remove() blocks and waits for queue to have something if queue is empty
  - offer() waits for space to be avaliable for specified amount of time


there are more queues like

 - linkedblockingqueue
  backed by linked list
  has two locks so more concurrent

 - priorityblockingqueue
  same as priorityqueue just threadsafe


 - Syncronusqueue
  can store atmost one element
  cant put element until previously added is removed

 - delayqueue
  has to wait to expire the delay of previously added element
  the element can only be such object whose class extends Delayed interface
  backed by priority queue


 - concurrentlinkedqueue
  lock free thread safe queue
  can perform put put or put reomove from two diff threads simultenously
  uses compare and swap method internally
