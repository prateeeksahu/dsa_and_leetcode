from what I have understood is that abstraction is way of hiding implementation of logic of how certain logic works in an interface or abstract class

> we create an interface and decalre certain methods in it

> then we use these interface or abstract class in child and class and provide its implementation

> then in main we create ref of abstract class or interface and object of child class

> ref class only has declartion of the method, logic is written in child class

> in that way client only knows that ref class only has a method, but it does not knows the imolementation

code 

abstract class Shape {
    // Abstract method (does not have a body)
    abstract void draw();

    // Regular method
    void display() {
        System.out.println("Displaying shape...");
    }
}

class Circle extends Shape {
    // Providing the implementation of the abstract method
    void draw() {
        System.out.println("Drawing a Circle");
    }
}

class Rectangle extends Shape {
    // Providing the implementation of the abstract method
    void draw() {
        System.out.println("Drawing a Rectangle");
    }
}


public class Main {
    public static void main(String[] args) {
        Shape circle = new Circle(); // Circle object created
        circle.draw();  // Output: Drawing a Circle
        circle.display();  // Output: Displaying shape...

        Shape rectangle = new Rectangle(); // Rectangle object created
        rectangle.draw();  // Output: Drawing a Rectangle
        rectangle.display();  // Output: Displaying shape...
    }
}


from Whom in This Example?


* From the client/user (in Main class): The details of how the shapes are drawn (i.e., the logic inside the draw()method) are hidden.
  The user doesn't know how a Circle is drawn or how a Rectangle is drawn — they just know that calling the draw() method will make the shape appear.

* From the client/user: The abstract method draw() is hidden, and the actual implementation is provided in the concrete classes (Circle, Rectangle).

* From the client/user: The user is not concerned about the class type (Circle or Rectangle) but just interacts with the Shape reference.

Benefits of Abstraction:
Hides Complexity: The user does not need to know the internal details of how the shape is drawn — they only need to know how to interact with the Shape object.
Improves Code Maintainability: If you need to change the way a Circle is drawn, you can change the code in the Circle class without affecting the Main class or other code that uses Shape.
Promotes Flexibility: You can add new types of Shape (like Triangle, Square, etc.) without modifying existing code, as long as they implement the draw() method.
