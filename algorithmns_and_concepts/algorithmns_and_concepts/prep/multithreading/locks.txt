The problem with syncronized is there is time limit for thread to wait.. so if one thread if stuck for enternity another thread will never get a chance to enter

So locks are introduced in java... lock is an intterface in java that has function that allows us to wait for few seconds or so

for that we first create an object of ReentrantLock with lock reference 

        private final Lock lock = new ReentrantLock();

now we can use the methods written in it

lock.trylock() - locks and return true if lock avaliable else returns false

lock.tryLock(1000, TimeUnit.MILLISECONDS) -  will wait for timespecified otherwise returns false

lock.unloch() - releases the resource for other thread to enter

------------------------------------------------

	•	lock() → waits indefinitely until the lock is free.
	•	tryLock() → tries to acquire immediately; returns true/false.
	•	tryLock(timeout, unit) → waits for a certain time, then either gets the lock or gives up.
	•	unlock() → releases the lock. (⚠️ Always in finally block, else deadlocks can happen.)

code - 

import java.util.concurrent.locks.ReentrantLock;
import java.util.concurrent.TimeUnit;

class SharedResource {
    private final ReentrantLock lock = new ReentrantLock();

    public void access(String threadName) {
        try {
            System.out.println(threadName + " trying to acquire lock...");
            
            // Try to acquire lock within 1000ms
            if (lock.tryLock(1000, TimeUnit.MILLISECONDS)) {
                try {
                    System.out.println(threadName + " got the lock!");
                    Thread.sleep(2000); // simulate work
                } finally {
                    lock.unlock(); // always release
                    System.out.println(threadName + " released the lock.");
                }
            } else {
                System.out.println(threadName + " could NOT get the lock (timeout).");
            }
        } catch (InterruptedException e) {
            System.out.println(threadName + " was interrupted.");
        }
    }
}

public class TryLockExample {
    public static void main(String[] args) {
        SharedResource resource = new SharedResource();

        Runnable task = () -> {
            String name = Thread.currentThread().getName();
            resource.access(name);
        };

        Thread t1 = new Thread(task, "Thread-1");
        Thread t2 = new Thread(task, "Thread-2");

        t1.start();
        t2.start();
    }
}

Expected Output (order may vary)

Thread-1 trying to acquire lock...
Thread-1 got the lock!
Thread-2 trying to acquire lock...
Thread-2 could NOT get the lock (timeout).
Thread-1 released the lock.

what is ReentrantLock?

when in a block of code you lock something twice or more or say dead lock occurs you cannot access lock again.

but in reentranctLock you can lock more than once.. a count is maintained how many times lock was called.

The lock isn't opened until unlock is called same number times lock was called


since you can enter a lock number of times it is called re entrant
