> executor framework helps us run thread

> we dont need to create the thread by ourselves.. we just need to give it the logic and specify the number of threads to be created.. it will manage the task accordingly

> we can reuse threads in this framework, so threds are not killed and made again, this reduces the computatinonal usage

next what ever you wanna do pass it in submit function.. takes Runnable as input

executor.submit(() -> {

then to stop the threads use shutdown function 

executor.shutdown();

remember this funtion donot wait for threads to finish to move to next code of line, it just like a watchman who has duty to close the pool once all threads job is done... once this line is encountered this watchman stats looking at threads and moves on to next line

to wait for control to move to next line before threads ends use this after shutdown

	try {

            throw new RuntimeException(e);
        }

> ExecutorService implements Executor interface and it has only execute method... if you create pool using executor reference you can have a pool but you wont be able to use shutdown

> execute method has the void return type but submit has the a Future<?> retrun type, that means we can return anything after submit is executed, ? is explained in generics

this is how code will look like

public class executorServiceReturn {
    public static void main(String[] args) throws ExecutionException, InterruptedException {
        ExecutorService executorService = Executors.newSingleThreadExecutor();
        Future<Integer> submit = executorService.submit(() -> 42);
        System.out.println(submit.get());
        executorService.shutdown();
    }
}

> Invokeall is the method that takes callables as the list and execute all of them at once once

> when it does so it locks main thread, so main waits till invoke all is finished to go ahead

here is the code 

public static void main(String[] args) throws ExecutionException, InterruptedException {
        ExecutorService executorService = Executors.newSingleThreadExecutor();

        Callable<Integer> c1 = () -> {
            System.out.println("Task 1");
            return 1;
        };

        Callable<Integer> c2 = () -> {
            System.out.println("Task 2");
            return 2;
        };

        Callable<Integer> c3 = () -> {
            System.out.println("Task 3");
            return 3;
        };

        List<Callable<Integer>> l = Arrays.asList(c1, c2, c3);
        List<Future<Integer>> futures = executorService.invokeAll(l);
        for(Future<Integer> f : futures) System.out.println(f.get());
        executorService.shutdown();

    }
}


> invokeany is the method that returns directly a value not a future

> no matter how many clonable you pass it runs all, but returns the one that was completed first

 Integer futures = executorService.invokeAny(l);

 ScheduledExecutorService schedules the execution for givem time

 it has 2 methods

 schedule - just takes runnable and the time delay

 scheduleAtFixedRate - takes runnable, initial delay and time period and executes first thread after initial delay then executes rest after given period, overlapping can happen

 scheduleWithFixedDelay - takes runnable, initial delay and delay, same as previous just after previous execution when to strt next is specified by delay

 below is the code 

public static void main(String[] args) throws ExecutionException, InterruptedException {
        ScheduledExecutorService s = Executors.newScheduledThreadPool(3);
        s.scheduleAtFixedRate(() -> System.out.println("hi"), 2,5, TimeUnit.SECONDS);
        s.scheduleWithFixedDelay(() -> System.out.println("hi"), 2,5, TimeUnit.SECONDS);
        s.schedule(() -> {
            System.out.println("terminating");
            s.shutdown();
        }, 30 , TimeUnit.SECONDS);

    }
