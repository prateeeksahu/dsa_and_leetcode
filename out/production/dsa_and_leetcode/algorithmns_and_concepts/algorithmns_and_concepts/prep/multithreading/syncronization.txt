> When same object is passed in two or more threads and an operation is being performed in that object, there might be a chance that threads perform the operation on same time, which should not be happening

threads woking on shared resource 

ex code -

Counter class - 

public class Counter {
    int c = 0;

    public void incr(){
        c++;
    }

    public int getC(){
        return c;
    }
}


Thread class

public class MyThread extends Thread {
    public Counter counter;

    public MyThread(Counter counter){
        this.counter = counter;
    }

    public void run(){
        for(int i = 0; i< 1000; i++) counter.incr();
    }
}


Main class

public class syncTest {
    public static void main(String[] args) {
        Counter counter = new Counter();
        MyThread m1 = new MyThread(counter);
        MyThread m2 = new MyThread(counter);

        m1.start();
        m2.start();

        try {
            m2.join();
            m1.join();
        } catch (Exception e) {

        }

        System.out.println(counter.getC());

    }
}


the output of this code will not be always be 2000, it will sometimes be less than 2000, because threads are executing paralley this condition is calles raise condition

to fix this we use synchronized keyword. it wont let anyother thread do anything until the pervious one finishes it

code - 

  public synchronized void incr(){
        c++;
    }

this is called mutual exclusion. this ensures that multiple threads donot access critical resource simutenously

-------------------------------------
now lets say you didnot want to make entire method syncronized.. you only want a block of code to be syncronized... then you will use syncronized block


 public synchronized void incr(){
        synchronized (this){
            c++;
        }
    }

this is used to refer only this object
