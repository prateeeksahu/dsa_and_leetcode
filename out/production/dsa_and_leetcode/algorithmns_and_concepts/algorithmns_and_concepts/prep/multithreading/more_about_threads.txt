Internally all methods are executed in thread.. typically main thread, but they are not threads 

	•	All your code always runs inside some thread.
	•	By default, it’s the main thread created by JVM when your program starts.
	•	Other methods are not threads by themselves, they’re just instructions executed by whichever thread calls them.

--------------------------------

 Thread priority - 

there are 3 priority for thread

java.lang.Thread.MIN PRIORITY= 1
java.lang.Thread.NORM PRIORITY = 5
java.lang.Thread.MAX PRIORITY = 10

the thread scheduler assigns the processor to a thread based on the priority of the thread

we can set priority any number between 1-10

	t.setPriority(Thread.MAX_PRIORITY);
	t.setPriority(10);

both ways are valid

start() - calls run internally and starts the thread (well not directly but after 2-3 methods chaining, checks some syncronization and stuff)

run() - logic of the thread is written inside here 

sleep() - suspends the thread for given period of time in milisceonds (has to be used with try catch)

	try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            throw new RuntimeException(e);
        }

like this

join() - waits for a thread to finish until anything else is executed (thread1.join())

interrupt() - just wakes the thread if in blocked or waitng or running state and stops the thread from doing anything or whatever it was doing

yield() - hints cpu that you can finish other threads as well.. it is not necessary to finish this thread

User threads - threads created by us.. writing some logic are called user thread. JVM waits till these threads are closed before closing the application

daemon threads - threads that run in background (like garbage collector). JVM never waits for these threads to end. once user threads ends it closes the application no matter if daemon threads were running

You can set user thread as daemon thread

	t.setDaemon(true);

both methods declare in their signature that they can throw InterruptedException.

public static native void sleep(long millis) throws InterruptedException;
public final void join() throws InterruptedException;


It means:
	•	Normally, sleep/join will block the thread.
	•	But if someone interrupts, the blocked state ends early.
	•	The JVM throws InterruptedException so that your code can decide:
	•	Stop what you were doing (graceful shutdown)
	•	Retry
	•	Propagate the exception further

This is Java’s way of letting threads cooperate instead of killing them forcefully.


Imagine you’re taking a nap (sleep()).
Your friend comes and shakes you awake (interrupt()).
You wake up earlier than expected and say:
“Oh, I was interrupted — now I’ll stop sleeping and do something else.”
That “something else” is the code inside your catch.
